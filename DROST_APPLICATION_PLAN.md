## Context
Build Drost as a Rust/GPUI desktop application inspired by T3 Code for managing projects and coding harnesses, with Zed-style layouts and dispatch plus tracking of software-factory runs. The user selected a coding workspace with one live interactive harness and conversation history alongside factory integration, rather than broad T3 parity or a factory-only workspace. Vim behavior includes real text editing in prompt/task fields; use installed Neovim with an isolated Drost-controlled configuration.

## Verified starting state
- `Cargo.toml` defines package `drost` version `0.1.0`, Rust edition `2024`, with no dependencies.
- `src/main.rs` only prints `Hello, world!`; there are no existing application modules to reuse.
- The user-supplied `~/dev/ComplianceSoftwareFactory` path does not exist in this environment. The local factory repository is `/Users/tim/dev/compliance-software-factory`. Xcode is selected at `/Applications/Xcode.app/Contents/Developer`.
- Installed executables discovered: `/opt/homebrew/bin/omp` (Homebrew 18.2.0), `/opt/homebrew/bin/nvim` (verified `NVIM v0.12.3`), `/Users/tim/.local/bin/factory`. Factory binary/source compatibility is unverified — confirm its help/version before launching.
- Reference inspiration is https://github.com/pingdotgg/t3code; use workflow/layout concepts, not its branding or a copy of its server architecture.

## Approach
Implement steps in order; steps 3 (OMP) and 4 (Neovim) can be developed independently after steps 1–2, but submission wiring is complete only when both are integrated. Each step must leave `cargo check` passing with its visible controls wired to real behavior; do not expose mock conversations or fake run rows while integrating.


### 1. Establish the desktop and durable project workspace
Keep one Rust package and replace `src/main.rs` with GPUI application startup, backed by `src/lib.rs`, `src/app.rs`, `src/store.rs` and `src/model.rs`. These are new paths because the repository has no application implementation to reuse. Pin `gpui-kit = "=0.6.1"` and use its re-exported GPUI types exclusively. Follow https://raw.githubusercontent.com/longbridge/gpui-kit/v0.6.1/examples/input/src/main.rs for Root/application setup and https://raw.githubusercontent.com/longbridge/gpui-kit/v0.6.1/examples/dock/src/main.rs for dock setup. Do not import Zed's application/editor crates.

Use `rusqlite` with bundled SQLite, `serde`/`serde_json`, `uuid` v4 IDs, `anyhow`, `thiserror`, `async-channel`, `smol` and `libc` for the concrete modules, plus `image` (PNG/JPEG/WebP codecs) and `base64`. Resolve compatible published releases and commit Cargo.lock. Tagged GPUI Kit 0.6.1 declares compatible `gpui-pre*` 0.3.1 requirements; let its facade select the matching family and lock it, without separately importing upstream GPUI. Neovim transport uses `rmpv = "=1.3.1"` (MIT, verified published manifest), not an additional editor framework or an LGPL Rust client binding.

Application data defaults to `~/Library/Application Support/Drost`; `DROST_DATA_DIR` overrides the whole directory for isolated verification. Open `drost.sqlite3` with foreign keys enabled and a single serialized background database owner. Schema version is SQLite `user_version = 1`. Use these tables (all IDs are UUID strings, timestamps UTC RFC3339 text):
- `settings(key TEXT PRIMARY KEY, value_json TEXT NOT NULL)`.
- `projects(id TEXT PRIMARY KEY, name TEXT NOT NULL, root TEXT UNIQUE NOT NULL, archived INTEGER NOT NULL DEFAULT 0, defaults_json TEXT NOT NULL)`.
- `threads(id TEXT PRIMARY KEY, project_id TEXT NOT NULL REFERENCES projects(id), title TEXT NOT NULL, harness TEXT NOT NULL, session_ref TEXT, model_json TEXT, draft TEXT NOT NULL DEFAULT '', attachments_json TEXT NOT NULL DEFAULT '[]', submission_json TEXT, archived INTEGER NOT NULL DEFAULT 0, created_at TEXT NOT NULL, updated_at TEXT NOT NULL)`.
- `factory_launches(id TEXT PRIMARY KEY, project_id TEXT NOT NULL REFERENCES projects(id), thread_id TEXT REFERENCES threads(id), descriptor_json TEXT NOT NULL, event_path TEXT UNIQUE, work_item_id INTEGER, attempt_id TEXT, process_exit INTEGER, launch_error TEXT, created_at TEXT NOT NULL)`.

Store global `executables` (keys `omp`, `nvim`, `factory`), `factory_data_root`, `layout` and `selected_thread` in settings. Resolve an explicitly configured executable first; otherwise PATH then `/opt/homebrew/bin`, `/usr/local/bin`, `~/.local/bin`. Show resolved paths and diagnostics in Settings. Do not install/authenticate/upgrade tools automatically. Default factory root to `FACTORY_DATA_ROOT`, then `$XDG_CACHE_HOME/compliance-software-factory`, then `~/.cache/compliance-software-factory`; persist the chosen absolute root. Do not create per-launch data roots: that would bypass shared capacity accounting.

Project defaults JSON has `interactive_model: null | {provider,id}`, `factory_harness: "omp"`, `factory_model: null | string`, `factory_thought_level: null | string`, `factory_target_branch: null | string`. Model null means use the harness's configured default; never bake a model version into Drost.

Register existing working trees via folder picker or path field. Resolve `git -C <folder> rev-parse --show-toplevel`; reject bare repositories/non-Git folders and deduplicate canonical worktree roots, selecting the existing record on duplicate. Support project rename/archive and thread create/rename/archive; archive retains history and never deletes checkout/session/factory files. Reject archive while the affected thread/project has active interactive turns or owned Factory processes. Missing/unreadable roots remain visible with an error and cannot launch work.

Persist drafts, attachment references and layout changes off the render thread; flush pending state on orderly quit. If storage cannot be written, keep existing in-memory drafts, show the error and disable new submissions/dispatches rather than launching untracked work. Unsupported newer schema or corrupt DB opens a recovery/error screen without overwriting the file. Concurrent app instances must not own the same data directory: take an exclusive advisory lock on `<data>/instance.lock` for the GUI lifetime; a second instance reports the conflict and exits.

Add `src/ui/{mod,workspace,sidebar,conversation,factory,settings,commands}.rs`. Use a dark graphite palette: window `#181B20`, panels `#20242B`, borders `#343A46`, text `#D8DEE9`, muted `#8B95A5`, accent `#7AA2F7`; use system UI font and monospace for code/editor/logs. Initial window 1440×900, minimum 900×600. Keep spacing compact, borders subtle, and controls real rather than populated demo data.

Use GPUI Kit DockArea with persistent layout version `1`: left Projects panel 260px; center session tabs showing conversation and composer; right Factory panel 340px, collapsible; bottom output/detail panel 240px, initially collapsed; status bar with focused region, Neovim mode, project branch and active counts. Restore valid layout, otherwise restore these defaults and report only the layout issue. `Reset Layout` resets layout, not application data. Read-only branch display comes from Git; no source editor/worktree manager is added to this scope.

Sidebar groups threads by project and offers an explicit archived-history toggle. Thread rows show title, model and lifecycle badge; factory rows show task title/source, harness/model, attempt and last reported state. Empty workspace offers Add Project; empty project offers New Conversation and Send to Factory. Selected factory details show tasks, stages, advisory agent notes, logs and artifact paths, with Reveal in Finder and copy-path actions; no fabricated progress percentage or inferred PR URL.

Focus contexts are `Workspace`, `List`, `Conversation`, `NvimEditor`, `NativeInput`, `CommandPalette`, `Dialog`. Use typed GPUI actions and context-scoped bindings. Outside text entry: `j/k` or arrows select/scroll, `gg/G` jump first/last, `h/l` collapse/expand project groups, Return opens selection. `Ctrl-h/j/k/l` moves spatial pane focus from workspace/list/conversation only. In native text inputs, normal typing is not intercepted.

Global `Cmd-Shift-P` opens the palette; `Cmd-1` focuses Projects, `Cmd-2` Conversation, `Cmd-3` Factory, `Cmd-4` Output. `Cmd-n` creates a conversation in the selected project; `Cmd-,` opens Settings. `i` from Conversation focuses its Neovim composer; `Escape` inside Neovim stays Neovim's Normal-mode action, while `Cmd-Escape` leaves editor focus for the conversation. `Cmd-Return` submits a prompt or confirms the factory task form; Return is always newline/Neovim behavior inside an editor. `Cmd-.` interrupts an active conversation turn. Do not bind Ctrl-w globally: Neovim owns it while focused.

Palette commands: Add Project, New Conversation, Rename Project, Archive Project, Rename Conversation, Archive Conversation, Show Archived, Send to Factory, Open Factory Folder, Dispatch Azure Work Item, Refresh Factory Runs, Settings, Reset Layout. Palette filters these commands and project/thread titles; Enter executes/selects, Escape dismisses and restores prior focus. Mouse controls invoke the same actions, with disabled states explaining missing project/configuration or active-turn restrictions.

### 3. Implement native OMP conversations behind one small seam
Add `src/harness/{mod,omp}.rs`; only `omp.rs` understands OMP wire fields. No equivalent exists in the starter. Native RPC at installed OMP `18.2.0` is the selected protocol, not ACP: it exposes model discovery, durable history, text/images and extension UI. Ground implementation in the pinned source `https://raw.githubusercontent.com/can1357/oh-my-pi/v18.2.0/docs/rpc.md` and adjacent `packages/coding-agent/src/modes/rpc/{rpc-types,rpc-mode,rpc-frame}.ts`. Keep runtime work off the UI thread and deliver bounded event batches to GPUI entities; render virtualized history and tool output instead of rebuilding/copying the entire conversation per token.

The future-harness seam is a concrete handle, not a plugin framework:
```rust
pub async fn open(config: ConversationConfig) -> anyhow::Result<ConversationHandle>;
pub struct ConversationHandle {
    pub commands: async_channel::Sender<ConversationCommand>,
    pub events: async_channel::Receiver<ConversationEvent>,
}
```
`ConversationConfig` contains `harness: String` (only `"omp"` accepted now), resolved executable, canonical cwd, thread-specific session directory, optional opaque session reference and optional `ModelKey { provider: String, id: String }`. `ConversationCommand` variants are `Submit { request_id: Uuid, text: String, images: Vec<ImageAttachment> }`, `Interrupt`, `SelectModel(ModelKey)`, `LoadHistory { cursor: Option<String> }`, `Respond { request_id: String, answer: UserAnswer }`, `Close`. `UserAnswer` is `Value(String) | Confirmed(bool) | Cancelled { timed_out: bool }`. Images carry MIME plus owned file reference; only the OMP adapter base64-encodes them.

`ConversationEvent` variants are `Ready { session_ref: String, models: Vec<ModelChoice> }`, `StateChanged(ConversationState)`, `History { messages: Vec<Message>, next_cursor: Option<String> }`, `MessageUpdated(Message)`, `ToolUpdated(ToolActivity)`, `UserRequest(UserRequest)`, `Notice { level: String, text: String }`, `Failed { request_id: Option<Uuid>, message: String }`. Keep normalized data limited to what UI renders: message role/content blocks (Text, Thinking, Image), tool ID/name/input/result/error state, and user-request ID/kind/title/options/text/deadline. Preserve unknown payloads for a collapsed diagnostic view, not provider-specific widget branches. `ConversationState` is `Starting | Ready | Running | WaitingForInput | Interrupting | Disconnected | Failed`. Turn outcomes (Completed, Interrupted, Failed) belong to the turn, not the durable thread.
The turn outcome type also includes `Unknown` for lost connection/submission outcomes; the UI must distinguish it from a confirmed interruption. Future adapters implement this same handle contract without exposing their wire objects to views.

Spawn one OMP child per opened conversation, lazily; active sessions continue when switching tabs. Command is `omp --mode rpc --cwd <project-root> --session-dir <data>/omp-sessions/<thread-id> [--resume <exact-saved-session-id>]`, with OS cwd equal to the project root. Give the child its own POSIX session/process group; stdin/stdout are pipes and stderr is drained separately to diagnostics. Do not pass `--no-session`, clone credentials, or override OMP tool/approval configuration. Show that OMP runs with local user privileges and configured policy, not Factory's Docker sandbox. Close idle sessions when their tab is closed and resume on reopen; closing a running tab leaves its thread active and reachable in the sidebar.

Transport contract:
1. Read `ready` and require advertised protocol v2; send `{"id":"<unique>","type":"negotiate_protocol","protocolVersion":2}` and wait for successful negotiation before requesting history. No lossy v1 fallback for this native image/history surface.
2. All commands/responses are newline-delimited JSON. Match command responses by `id`, never arrival order; unsolicited events remain consumable while any request is waiting.
3. Enforce physical stdout frames ≤1,048,576 bytes including newline; reassemble v2 `rpc_chunk` exactly like pinned `RpcFrameDecoder`: contiguous same `chunkId`, sequential indices from zero, matching count/byteLength, strict base64/UTF-8, ≤262,144 decoded bytes per chunk, total ≤67,108,864 bytes, no unrelated interleaved frames. Reject malformed/truncated sequences and surface a transport error without treating partial messages as completed.
4. Give control requests a 30-second timeout; model discovery can take 60 seconds. A timed-out submission is outcome-unknown and must never be automatically resent. A turn itself has no artificial elapsed-time timeout; Stop remains available. EOF/process exit fails outstanding commands and marks an active turn Interrupted/Unknown, never Completed.

Initialize with `get_state` and `get_available_models`; persist the returned session reference as JSON string `{id, file, cwd, session_dir}` using `sessionId`, optional `sessionFile`, and the known cwd/directory. Persist it before accepting a prompt. Load history through `{"type":"get_messages_page","limit":128,"cursor":"<optional>"}`; cursor is transient. `session_busy` waits for idle; `stale_cursor` discards the partial walk and restarts it at idle. On missing saved session files, show recovery/error and offer an explicitly new conversation; do not silently replace a lost conversation with an empty one. An unsent draft with no durable provider history can initialize a new provider session when first opened.

Model selector uses exact returned `provider`/`id`, display `name`, and `input` capabilities. `set_model` wire is `{"type":"set_model","provider":"...","modelId":"..."}`; apply/persist only on success, disabled while a turn is active. Missing auth/model or a discovery error is a visible setup issue with a retry action; no hardcoded model or simulated response.

Before submission, obtain the ordered Neovim snapshot from step 4 and persist `submission_json = {request_id,text,attachments,state:"pending"}`. Send `{"id":"<request-id>","type":"prompt","message":"<text>","images":[{"type":"image","mimeType":"image/png","data":"<base64>"}]}` (omit images when none). Exactly one foreground turn per conversation; disable Send while running rather than introducing queue semantics. Empty text with no images is rejected.

An immediate successful prompt response is acceptance, not completion. Persist submission state `accepted`; clear the composer only if it still matches the submitted draft revision. Keep submission recovery data until terminal/local completion. A same-ID failure may arrive after the ack: mark failure and offer Restore Submitted Draft without overwriting newer typing. `agent_start`/`turn_start` establish activity; `agent_end` completes only when `isTerminal != false`. `data.agentInvoked:false` or `prompt_result` with the same ID completes a local slash-command prompt without waiting for `agent_end`; render its `command_output` text. Never auto-resend a pending/accepted submission on reconnect.

Render `message_start/update/end` using the message snapshot as canonical content, with text/thinking deltas where needed for smooth updates; reconcile rather than append the final message twice. Render `tool_execution_start/update/end` by `toolCallId` with collapsible inputs/results and failure badges. At idle/terminal settlement reload paged history to converge with durable messages. Reuse `gpui_kit::component::text::markdown(...).selectable(true).on_link_click(...)` from the tagged `examples/markdown/src/main.rs`; do not reproduce its demo plugins, executable code-block actions or a separate Markdown engine. Only explicitly clicked HTTP(S) links open externally. Render unsupported raw HTML inertly and large results collapsed; provider image content uses the dedicated native image path.

Native images:
- File-picker or drag/drop attachment of PNG/JPEG/WebP; copy accepted originals into `<data>/attachments/<uuid>.<extension>` before persisting references, so moving the source file does not break a draft. Verify bytes/MIME with the Rust `image` decoder off-thread; cap decoded images at 32 megapixels and selected files at 20 MiB, with explicit errors.
- Display thumbnails and click-to-enlarge previews; gate sending on the selected model advertising `"image"`. Normal provider errors remain visible even when capabilities advertised support.
- Keep the unchunked outgoing JSON command within OMP's recommended 1 MiB physical budget. If originals exceed it, offer an explicit `Optimize images for sending` action: retain originals, make JPEG copies flattened against white, resize longest side to at most 2048px, quality 85, and halve dimensions until the entire request fits or a 256px longest side would be exceeded. Show the actual prepared previews and dimensions before send; if text alone or prepared images still exceed the budget, keep the draft and require removal/reduction. Never silently truncate images or text.
- Decode image content in provider messages/tool results and display it natively; unknown MIME/corrupt/oversized content shows a per-image error without discarding the surrounding message. OMP owns persisted history/blob resolution: do not parse its blob store directly or treat arbitrary assistant strings as local image paths.

Map extension UI requests in the native workspace:
- `confirm`, `select` (with option descriptions), `input`, `editor` become user requests; editor uses the Neovim editor module. Replies are `extension_ui_response` with `confirmed`, `value`, or `cancelled:true`; timeout adds `timedOut:true`. Empty select options are cancellable, not a hanging dialog.
- `cancel.targetId` dismisses exactly that pending request; timeout/interrupt/session close dismisses requests and never sends an affirmative default. Preserve per-thread pending requests and badge WaitingForInput without stealing focus from another project.
- `notify`, `setStatus`, `setWidget`, `setTitle` update notices/status/plain-text widget lines/title; `set_editor_text` updates an empty composer or asks before replacing a nonempty local draft. `open_url` shows a user-clickable HTTP(S) URL, never auto-opens arbitrary schemes.
- Unknown interactive request methods are cancelled with a visible unsupported-request warning. Do not register host tools/URI schemes or expose automatic Factory dispatch to the agent in this build. RPC has no universal `request_permission` event; do not claim every local tool call is separately approved by Drost.

Interrupt sends `{"type":"abort","id":"<unique>"}` and leaves the turn Interrupting until terminal/idle confirmation. On orderly app quit, notify that active interactive turns will stop (Factory jobs continue), send abort for active turns, close OMP stdin, wait up to 5 seconds, then terminate only the still-owned process group if necessary. Pending drafts/submissions and provider session references remain durable. On crash/restart, opening a thread resumes its saved session and history, without replaying input.

Focused checks for this step: real OMP ready/negotiation/state/model discovery and invalid model selection without inference; parser tests for reordered responses and invalid/interrupted chunks; `agent_end {isTerminal:false}` followed by continuation must stay Running; same-ID late prompt failure must preserve submitted text; a local-only `prompt_result` must settle; extension request cancel/timeout must never approve; real authenticated image prompt/history reload and stop/continue at the UI surface.

### 4. Make Neovim the actual prompt/task editor
Add `src/neovim/{mod,rpc,session,grid,input}.rs` and a bundled `src/neovim/bridge.lua`. There is no existing editor to reuse. Use Neovim's own editing and redraw engine rather than a GPUI editor plus a Vim-emulation layer. Reuse GPUI's platform-input pattern from the tagged `crates/base/src/input/base/state.rs`; keep the existing input controls for simple settings/title fields.

**Transport and lifetime.** One isolated Neovim child per Drost window, with a separate unlisted scratch buffer for each conversation draft, factory draft, or extension editor request. This preserves per-buffer undo and shared Vim registers without one process per text field. Start `<nvim> --embed --clean -u NONE -i NONE --noplugin -n`; do not add `--headless`, since an embedded UI attaches before startup finishes. Use direct piped stdio MessagePack-RPC with `rmpv`; no PTY, TCP listener or personal init/plugins/ShaDa. Preserve the installed Neovim runtime directory.

`rpc.rs` owns a narrow private `call(method, args)`/notification transport implementing the documented arrays: request `[0,id,method,args]`, response `[1,id,error,result]`, notification `[2,method,args]`. Dedicated blocking reader/writer threads keep MessagePack I/O off GPUI; a serialized command actor owns pending requests and ordering. The reader must continue servicing Neovim requests (notably clipboard) while a client call is outstanding; correlate responses by integer ID and serialize server replies in Neovim's documented reverse-request order. Retain typed MessagePack EXT handles, not JSON coercions. EOF, decode failure or a non-null RPC error settles the affected request; channel failure settles all outstanding requests.

After `nvim_get_api_info`, retain the actual channel ID, verify `ext_linegrid`/`ext_cmdline` and required methods are advertised, and set client info to Drost. Install a one-shot `VimEnter` notification before attaching so scratch-buffer setup waits for completed startup. Attach via `nvim_ui_attach(cols, rows, {rgb=true, ext_linegrid=true, ext_cmdline=true})`. Leave `ext_multigrid`, `ext_messages`, `ext_popupmenu`, `ext_hlstate` and `ext_tabline` off: Neovim renders messages/completion on the single grid; only its command line is externalized. Supporting fewer UI extensions avoids reimplementing completion/message presentation.

After VimEnter, initialize the Lua bridge, create each buffer using `nvim_create_buf(false,true)`, set `buftype=nofile`, `bufhidden=hide`, `swapfile=false`, `undofile=false`, and attach line-update notifications. Use `nvim_set_current_buf` and `nvim_buf_set_lines` for initial/restore contents. **Do not use `buftype=prompt`: the user needs a freely editable multiline document, not prompt-buffer restrictions or Enter-to-submit.** Set `wrap=true`, `linebreak=true`, `number=false`, `relativenumber=false`, `showtabline=0`, `laststatus=0`, `mouse=a`, and the Drost editor colors. Begin a newly focused empty draft in Insert mode. Escape is genuine Neovim Normal mode; Return inserts a normal newline. No source-file tree, LSP or personal plugins are added.

**Render what Neovim reports.** Maintain staging and committed single-grid snapshots. Process every parameter tuple in each `redraw` notification in order; publish changed grid rows/highlight entries only at `flush`, never partial batches. Implement `grid_resize`, `grid_line`, `grid_clear`, `grid_scroll`, `grid_cursor_goto`, `default_colors_set`, `hl_attr_define`, `mode_info_set`, `mode_change`, `option_set`, busy/mouse state, bell and flush. Handle optional `grid_destroy` defensively. Unknown events/extra fields are ignored; malformed known events disconnect the editor with a diagnostic, not a panic.

`grid_line`'s omitted highlight IDs inherit within the event and repeat counts occupy cells; preserve the empty continuation cell after a wide glyph. Draw runs in a monospace font at exact cell positions, retaining combining characters and wide cells; do not derive columns from Rust char count. Implement scrolling rectangles with overlap-safe moves, all foreground/background/reverse/bold/italic/underline/undercurl/strikethrough styling, and mode-specific cursor shape/blink. Use acknowledged grid dimensions to render after resize; coalesce resize requests through `nvim_ui_try_resize`.

Render external command-line events `cmdline_show/pos/special_char/hide` and `cmdline_block_show/append/hide` in an attached one-line/multiline strip. Preserve nesting levels and highlighted chunks. Byte cursor positions are converted to pixel positions by shaping the prefix, not by treating bytes as cells. Search, `:`, command completion and error messages must remain usable; because external popup/messages are off, render their grid cells rather than inventing parallel panels. Source: https://neovim.io/doc/user/api-ui-events/ and https://neovim.io/doc/user/api.html.

**Input and ordering.** `input.rs` implements GPUI `EntityInputHandler`/`ElementInputHandler` against a small buffer/command-line shadow for synchronous UTF-16 platform callbacks. The grid is still the display authority. Explicitly convert between UTF-16 platform ranges, UTF-8 Neovim buffer byte columns, and screen cells. Native composition is a temporary overlay; buffer updates carry the committed draft. Never register GPUI Kit EditorState as a second owner of the text.

Route printable physical text exactly once through `nvim_input` with literal `<` escaped as `<LT>`; route non-text keys as `<Esc>`, `<CR>`, `<BS>`, `<Del>`, `<Tab>`, arrows and modifier notation. Do not both forward a key event and its native text callback. Avoid mode-based guesses for fast sequences: Neovim decides whether arriving printable text is an operator or inserted text. Track accepted byte counts from `nvim_input`; queue/retry unaccepted suffixes and retain Unicode boundaries. Normal keys are never considered executed merely because this call returned.

Reserve `<F23>` as an input-drain marker in Normal/Insert/Visual/command-line modes and buffer-local `<F24>` as a snapshot marker in Normal/Insert/Visual modes. Install Lua mappings; a command-line drain mapping is an expression mapping that returns the empty string without changing the command. Each callback increments a Lua-owned sequence counter and notifies the host with that counter plus editor generation; allow only one outstanding marker and consume only its expected sequence. Physical F23/F24 input is reserved, not forwarded as user text. The snapshot callback reads `nvim_buf_get_changedtick(buf)`, `nvim_buf_get_lines(buf,0,-1,true)`, buffer ID and cursor, then emits `drost_snapshot`. These are Drost notification names over documented `vim.rpcnotify`. Disable submission/buffer-switching during command-line entry or IME preedit until completed/cancelled. A marker timing out after 2 seconds leaves the draft untouched and offers Cancel/Restart Editor; it never dispatches.

For paste/committed IME text, freeze later outbound actions, enqueue the drain marker after earlier raw keys, await its matching callback, then use `nvim_paste(text,false,-1)` and await its response before continuing. Require an unfinished operator to be completed/cancelled before native paste. For a nonempty native replacement range in a buffer, convert exact UTF-16 endpoints to row/UTF-8 columns and call `nvim_buf_set_text(buf,start_row,start_col,end_row,end_col,replacement_lines)`, then set the cursor after the inserted text; preserve Neovim undo. For command-line replacement, splice the verified shadow range and call `vim.fn.setcmdline(new_text,one_based_byte_cursor)` through Lua; a nonzero result preserves the draft and reports loss of command-line focus. Keep preedit updates only in a marked overlay anchored to the grid cursor; cancellation sends nothing. A changedtick/generation mismatch preserves recoverable composition text instead of overwriting another location.

Configure `vim.g.clipboard`: copy to `+`/`*` emits `drost_clipboard_set {lines,regtype}`; paste uses `vim.rpcrequest(chan,"drost_clipboard_get")` returning `[lines,regtype]`. Route clipboard operations asynchronously to the GPUI thread; the MessagePack reader continues processing while the UI callback obtains the current native clipboard and the writer sends the response. Never block GPUI waiting for Neovim or call platform clipboard APIs from the reader. On a 2-second clipboard timeout return an RPC error, not stale text. Preserve `v`, `V` and blockwise register types; use `clipboard=unnamedplus` and disable Neovim provider caching. Cmd-c/x use the actual visual selection via yank/delete; Cmd-v uses native contents through ordered paste. Mouse selection/scroll uses `nvim_input_mouse(...,grid=0,row,col)` and current cell geometry. Forward focus using `nvim_ui_set_focus` when advertised.

**Snapshot-before-submit and buffer switching.** `NvimEditor` exposes `open_draft(DraftKey,text)`, `focus_draft(DraftKey)`, `snapshot(DraftKey) -> DraftSnapshot`, `replace_if_revision(DraftKey,revision,text)`, and shutdown through its command channel; snapshots include key, generation, changedtick, text and cursor. DraftKey distinguishes thread, factory form and extension request. Buffer IDs/changedticks are transient and never reused after restarting Neovim.

Cmd-Return or Send freezes outbound editing, queues `<Esc><F24>` after all earlier input for that draft, and awaits the token-matched snapshot. Escape cancels an unfinished operator/selection and leaves Normal mode; it does not submit or delete text. The callback—not `nvim_input` returning, an arbitrary delay, or an unrelated `flush`—is the semantic barrier. Persist the immutable snapshot/submission before passing it to OMP or Factory. On acceptance, clear only the matching draft revision and reenter Insert mode; on rejection preserve text and restore editor focus. A newer revision is never cleared.

Switching drafts uses the same snapshot barrier before `nvim_set_current_buf`, so queued typing cannot land in the next conversation. Restore the selected buffer's cursor/mode only after activation; restore Insert mode for a fresh draft. Maintain per-draft in-memory text revisions from `nvim_buf_lines_event`, including chunked `more` updates; ignore display-only null changedticks as durable edits. Persist thread drafts in their row and factory drafts in settings key `factory_draft:<project-id>` containing title/body/origin and form fields. Extension editor buffers remain attached to their pending RPC request and are cancelled if that session closes.

**Failure behavior.** On child exit/transport error, disable editing, retain the latest committed text plus separately recoverable uncommitted composition, drop raw-key queues, and fail snapshot requests without dispatching anything. Show Restart Editor. Restart creates a new generation, reattaches the UI and recreates scratch buffers from saved drafts; stale messages cannot mutate them. Do not replay raw keys, auto-submit, or claim undo survives a Neovim process crash. Restore text/cursor and wait for a committed initial grid before reenabling input. Missing/unsupported Neovim disables multiline editing with an actionable Settings error; no silent approximate Vim fallback.

On normal quit, snapshot drafts first, stop accepting input, call `qa!` only after persistence, and wait for the owned child; terminate it after 2 seconds if unresponsive. This never writes editor buffers to project files.

- `story-loaded`: title/state/tags; `attempt-ready`: attempt ID, target branch, base SHA, mode, harness/model; `agent-selected`: actual harness/model.
- `task-dag-loaded`: task IDs/states and dependency links; `slice-started`: active task/branch; `slice-step-started/completed`: current step/outcome; `slice-merged`: task merged; `slice-failed`: task failure and diagnostic; `slice-parked`: task paused reason.

Separate `reported_state: Pending | Running | Completed | Failed | Paused` from `liveness: OwnedRunning | Exited(code) | Unverified`. A known child exiting without a terminal event is Interrupted/Unknown in the UI, not success even for exit 0.
